# 从 Clash Verge 迁移到 AX1OM Network

切换透明代理会改变流量接管方，已有 TCP 连接可能断开；SSH、聊天流式输出、下载和在线会议都可能需要重连。**不需要关闭 Wi-Fi 或拔掉网线。** 需要停止旧代理的 TUN 和核心，避免两个客户端同时接管流量。

首次迁移前请先知道这些影响，再决定何时执行切换。AX1OM 不会为了导入或测试而自动退出 Clash Verge；当前预发布版尚未完成真实 TUN 接管的长期验收。

## 先准备，继续使用原代理

1. 保留 Clash Verge、当前订阅、扩展配置与节点选择。不要先卸载原客户端。
2. 在 AX1OM 设置中点击“导入现有配置”，或在订阅管理中添加自己的 YAML / HTTPS 订阅；自建专线可通过“导入专线”添加 VLESS 链接或单节点文件。核对缓存、节点数量、认证完整性和业务出口。
3. 在设置中点击“生成配置”；有原配置时应用会保留前一份配置备份。
4. 关闭 TUN 开关后点击“启动独立代理”。这个模式不切换系统代理；让需要测试的应用显式使用 `127.0.0.1:17901` 的 HTTP / SOCKS 入口。
5. 检查所需业务、DNS 与直连例外。隔离测试只能验证被明确导向测试入口的请求，不代表全系统已迁移。
6. 选择可短暂重连的时间，结束重要下载和实时会话。保留本机迁移说明，避免网络暂断时无法查看。

导入完成后，AX1OM 使用自己保存的 Provider 与节点缓存，正常运行无需读取原客户端目录。导入不是自动接管，也不是两套配置的持续双向同步。

## 正式切换

1. 在 AX1OM 点击“停止内核”，停止独立测试核心，确保没有第二个 AX1OM 核心在运行。
2. 在 Clash Verge 关闭 TUN 和系统代理，再退出 Clash Verge。检查其旧核心已经停止；仅隐藏窗口不等于退出核心。
3. 对其他使用旧本机端口的工具，记录并检查其显式代理设置。固定指向旧端口的终端或客户端不会因为更换 TUN 自动改成新端口。
4. 在 AX1OM 打开 TUN 开关，点击“启动 TUN”，按 macOS 提示自行使用 Touch ID 或密码授权。密码由系统处理，不要写入订阅或配置。
5. 等待 AX1OM 显示独立核心正在运行、TUN 已启用，再重新建立需要代理的连接。
6. 验证目标业务的实际出口，并验证局域网、Tailscale 与国内直连应用。需要浏览器行为时，在实际浏览器中测试。

AX1OM 的启动检查会拒绝其他 Mihomo 核心仍在运行的情况，包括旧 Verge 核心。遇到此提示，返回原客户端完成退出；不要靠杀死所有网络进程、关闭防火墙或同时开启两套 TUN 解决。

管理员授权组件与程序当前采用临时签名，尚未公证。若 macOS 阻止打开或授权失败，应保留原代理并查明具体错误；不要关闭系统整体安全保护。

## 出问题时退回 Clash Verge

1. 在 AX1OM 点击“停止内核”，停止 TUN 核心，并等待其运行状态变为停止。
2. 打开保留的 Clash Verge，恢复之前的订阅与节点选择。
3. 重新开启 Clash Verge 的系统代理或 TUN，按照原先的使用方式恢复。
4. 重新建立业务连接并验证出口。此过程同样可能中断现有连接。
5. 保留 AX1OM 自己的配置备份用于本机排查；公开反馈前移除订阅、密钥、账号和真实连接内容。

确认原代理恢复之前，不要删除旧客户端或旧配置。AX1OM 的停止操作仅针对其记录并确认身份的独立核心，不会代替用户停止其他代理软件。

## 什么才算迁移完成

- 全系统只有一套透明代理接管；AX1OM 核心与 TUN 状态来自实际运行结果。
- 所需业务使用期望出口，客户端没有仍指向已关闭端口的旧代理设置。
- 国内应用、局域网和 Tailscale 正常；DNS 行为通过实际路径验收。
- 重启、睡眠唤醒与网络切换后的恢复经过验证。
- 旧代理仍可在停止 AX1OM 后恢复，回退方法已实际确认。

仅生成配置、通过语法校验或运行隔离测试，都不等于以上条件已完成。
